01.

なぜ 設計するのか

初級 → 中級 のパラダイムシフト

「書ける」 から 「設計できる」 へ。 紙の上で 1時間 考えた分、 実装は 3時間 速くなる。

📝 初級まで

  • 文法を 覚える
  • 1ファイルの スクリプト
  • 「書ける」が ゴール
  • 動けば OK

🚀 中級では

  • 設計の質 を 上げる
  • 複数ファイル＋サーバー
  • 「設計できる」が ゴール
  • 再利用できる 形に

⚠️ いきなり コードを 書くと…

  • 何を作るか 途中で 変わる → 書き直し
  • 機能が どんどん 増える → 終わらない
  • データの 形が ぐちゃぐちゃ → バグ多発

03.

スコープ管理（やる／やらない）

「やらないこと」を 決める

機能を 思いつくまま 入力 → ドラッグで「やる／やらない」に 分類。 やらないと 決めると 実装が 軽くなる！

🟢 やる（MVP）

🔴 やらない（後回し）

MVP = Minimum Viable Product（最小限の 動くもの）

06.

たしかめクイズ

3問 やってみよう

答えがわかったら 解説が出ます。

Q1. 良い 要件定義 に 必須 な 3要素は？
✅ 主語（誰）／状況（いつどこで）／動詞（何ができる）の3要素。 「すごい TODO」 はNG！
Q2. データモデルに 「id」 フィールド を 入れる理由は？
✅ 「歯みがき」が 2つあっても、id=1 と id=2 で 別物 と 区別できる。 削除・更新の キー になる。
Q3. 中級コースの 「設計から始める」 一番の メリットは？
✅ 設計に 1時間 → 実装が 3時間 速くなる。 「急がば回れ」 が プロのスタイル！
