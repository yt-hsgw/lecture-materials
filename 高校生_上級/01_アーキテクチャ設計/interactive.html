03.

ヘキサゴナル（ポート＆アダプタ）

体感

「外側 が 内側 に 依存」 を 可視化

中心 ＝ Domain、 外側 ＝ Adapter（API / DB / Mail）。 アダプタ を 切替 ボタン で 変えても **Domain は 変わらない**。 これ が ヘキサゴナル の 力。

DB: Mail:

⚓ Ports（Domain が 定義 する Interface）

  • interface UserRepository
  • interface Mailer
  • interface PaymentGateway

🔌 Adapters（Port を 実装 する 具象 class）

    💡 ヘキサゴナル の メリット

    Domain は どこ にも 依存 しない → テスト で InMemory / FakeMailer を 渡せる → **DB なし で ビジネスロジック が 検証可能**。 技術選定 を 後から 変えても Domain は 不変。

    05.

    クイズ で ふり返ろう

    3問チャレンジ

    Q1. 5人 / 100ユーザー / 立ち上げ3ヶ月 の Web サービス に **おすすめ** は？
    💡 小規模 / 初期段階 では モノリス（or モジュラー）が 王道。 マイクロ は 20人以上 から 検討。 Sam Newman 「まず モノリス で 作って 切り出せ」。
    Q2. **DDD の 集約**（Aggregate）の 主な 役割 は？
    💡 集約 は 「同時 に 変更 する もの」 ＝ 不変条件 を 守る 範囲。 集約ルート の メソッド を 通してしか 変更 できない。
    Q3. **ヘキサゴナル アーキテクチャ** の 核心 は？
    💡 Domain は どこにも 依存 しない → テスト で 別 アダプタ（InMemory 等）を 渡せる → DB なし で ロジック検証可能。
