3つ の テスト を ON / OFF する と、 該当 行 が 緑 / 赤 に 切り替わります。 「100% カバレッジ ＝ バグ ゼロ で は ない」 の 罠 も 体感。

💡 カバレッジ の 罠

100% カバレッジ で も 境界値（grade(60) は B？ C？） や 異常入力（負の値・null） を 検証 してない と バグ は 通る。 カバレッジ ＝ 「行 を 通った」 だけ。 「正しい こと を 検証 した」 の 保証 は 別。

04.

FizzBuzz TDD Quest

ハンズオン

5ステップ で TDD を 通す

RED → GREEN → REFACTOR を 5回 繰り返して FizzBuzz を 完成 させよう。 各 ステップ で **テスト 1個 ずつ** 追加 して、 通した あと 次へ。

STEP 1 / 5
テスト: fizzbuzz(1) === "1"
最初 の テスト。 まずは ハードコード で 通せば OK。「return '1'」 でも 緑 に なる！
▶ 「テスト 実行」 で 緑 / 赤 を 確認
05.

クイズ で ふり返ろう

3問チャレンジ

Q1. TDD の **緑** フェーズ で やる べき こと は？
💡 緑 は 「いま 失敗 してる テスト を 1個 通す」 だけ。 ハードコード でも OK。 美しさ は 次 の リファクタ で。
Q2. カバレッジ 100% の **意味** は？
💡 行 を 通る ＝ 正しい こと を 検証 した、 で は ない。 境界値 / 異常入力 を 別途 テスト する 必要。
Q3. テスト が 書き にくい コード の **原因** は？
💡 依存注入 で 外部依存 を **引数 で 渡す** と、 テスト では モック を 渡せる。 設計 が 良く なる シグナル。
