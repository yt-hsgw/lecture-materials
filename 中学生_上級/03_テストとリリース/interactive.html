06.

たしかめクイズ

3問 やってみよう

答えがわかったら 解説 が 出ます。

Q1. テストピラミッド で 「一番 多く 書くべき」 テスト は？
✅ ユニットテストを 厚く。 速くて 安いので 数百〜数千 書ける。
E2E は 重いので 厳選した 重要シナリオ だけ！
Q2. TDD の 正しい 順番 は？
✅ Red → Green → Refactor。 まず テストを 書いて 失敗 を 確認、 次に 最小 実装で 通す、 最後に きれいに 整える。
Q3. CI が 失敗（赤）した PR を どうする？
✅ 「赤い PR は マージしない」 が 鉄則。 main は 常に 動く 状態。
赤を 無視すると 本番が 壊れる → 全員が 困る！
