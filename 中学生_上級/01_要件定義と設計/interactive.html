01.

中級 vs 上級

個人開発 から チーム開発 へ

中級は 動けばOK、 上級は チームで作って 公開して 運用する。 4つの 観点で 比較。

📝 中級まで

  • 個人開発
  • localStorage で 永続化
  • 動けばOK
  • 手元で 動く

🚀 上級では

  • チーム開発・コードレビュー
  • DB + 認証
  • テスト・運用・セキュリティ
  • 公開して 他人に使ってもらう

💡 高校・専門・大学への 橋渡し

上級コースは 「学校の プログラミング授業」 や 「IT系専門学校 初年度」 の 基礎部分。
ここを 通れば、 進学先で 即戦力！

02.

ユーザーストーリー 作成ツール

「As a / I want / So that」

3つの 項目を 埋めると 業界標準の ユーザーストーリー が 完成。 MoSCoW で 優先順位 も 設定！

03.

DB スキーマ 設計ツール

テーブル → カラム → 自動 SQL 生成

テーブル を 追加 → カラム を 設定 → CREATE TABLE / JSON Schema 自動生成。
ER図 とも 連動 します！

💡 各フラグの 意味

P = PRIMARY KEY（主キー）／ N = NOT NULL（空NG）／ U = UNIQUE（重複NG）

04.

ER 図（リアルタイム）

上の DB設計 が そのまま 図 に

テーブルを 追加 / 編集 すると、 ここの ER図 が 自動で 描画されます。 外部キー は 線で つながる！

💡 外部キーの 書き方

カラム名を book_id のように 「他テーブル名 + _id」 で 命名すると、
自動的に 関連が 認識されます（FK 推定）。

05.

API 設計ツール

RESTful CRUD — 自動生成

リソース名（複数形）を 入力 → 5つの CRUD エンドポイント が 自動生成。 Flask / Express / curl も！

06.

たしかめクイズ

3問 やってみよう

答えがわかったら 解説 が 出ます。

Q1. ユーザーストーリー の 正しい 順番 は？
✅ As a [だれ] / I want [何が したい] / So that [どんな ためになる]。
業界標準 で、 アジャイル / スクラム 開発 で 必ず 使う 形式！
Q2. 外部キー（FOREIGN KEY） の 役割は？
✅ 別の テーブル の 主キー を 参照して、 関連を 表現。
例：reviews の user_id は users の id を 指す。
Q3. MoSCoW法 で 「Won't（今回はやらない）」 を 決める 意義は？
✅ 「全部やる」 と 1つも 完成しない。 「やらない」を 決めて 範囲を 絞る のが プロ。
第3回（リリース） で 動くもの を 持って いれる！
