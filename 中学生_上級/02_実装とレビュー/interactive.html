01.

Git ブランチ 可視化

ブランチ ＝ 並行する 開発の 線

ボタンで コミット / ブランチ / マージ を 体験。 緑が feature ブランチ、 紫が main。

💡 ブランチ命名規則

feature/xxx（新機能）／ bugfix/xxx（バグ修正）／ hotfix/xxx（緊急修正）／ chore/xxx（雑用）
type/動詞-名詞 の形式（例：feature/add-login）が ベストプラクティス！

02.

Pull Request シミュレータ

本物の GitHub に近い PR を 体験

PR タイトル・説明・差分・レビューコメント — すべての要素 を 1画面で。
下の レビュー結果 ボタンで マージ までの フロー も。

03.

コードレビュー 観点チェック

10項目 で 抜け漏れ なく

PR をマージする 前に この 10項目を 確認。 8つ以上 で 安心して マージ！

✅ テストが 全部 通っているCI が 緑になっている
📛 変数名・関数名 が 読んで わかるa ではなく userId
🔁 コードの 重複 がない（DRY）同じ処理 が 3回以上 ある → 関数化
🧪 テストが 追加 されている新機能 / バグ修正 には テスト
🔐 パスワードが ハッシュ化 されているbcrypt / scrypt / argon2
🛡️ 入力検証 が ある（バックエンド側）長さ / 型 / 形式 チェック
💉 SQL は パラメータ化 されている文字列連結 NG
🪤 HTML 出力 は エスケープ されているtextContent 推奨
🔑 APIキー / 秘密情報 が コードに ない環境変数（.env）に
📚 README が 更新 されている新機能の 使い方
0 / 10 完了
04.

パスワード ハッシュ デモ

「元に戻せない」 変換

パスワード を 入力 → ハッシュ化 の デモ。 同じパスワード でも 毎回 違うハッシュ（salt が 効くため）。

😱 平文（DB に そのまま 保存）
mypassword123
→
bcrypt
😊 ハッシュ（安全）
クリックで ハッシュ生成
💡 ポイント：
・ハッシュは 一方向 ＝ 元に戻せない
・salt を 混ぜるので 毎回 違うハッシュ
・検証時は「入力をハッシュ化 → 保存と一致 する？」を 比べる
・Pythonでは Werkzeug、 Node.js では bcrypt パッケージ を 使う

06.

  
たしかめクイズ






  
3問 やってみよう

  
答えがわかったら 解説 が 出ます。

  

    

      
Q1. Conventional Commits の 正しい例 は？

      

        
        
        
        
      

      
✅ type: 何をした の 形式。 feat / fix / docs / refactor / test / chore。
機械的に 変更ログ も 自動生成できる！

    


    

      
Q2. パスワード を DB に 保存する 正しい方法 は？

      

        
        
        
        
      

      
✅ bcrypt / scrypt / argon2 など 専用の パスワードハッシュ関数 を 使う。
Base64 や 単純な MD5 は NG（簡単に 元に戻せる）！

    


    

      
Q3. SQLインジェクション を 防ぐ 一番の 方法 は？

      

        
        
        
        
      

      
✅ execute("SELECT * FROM users WHERE name = ?", (input,)) のように パラメータで 渡す。
文字列連結 は 絶対 NG！ フロント検証 も サーバー検証 と 併用。
