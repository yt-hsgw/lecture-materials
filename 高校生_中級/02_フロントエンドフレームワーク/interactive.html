01.

useState ライブ シミュレータ

体感

「状態 が UI を 決定 する」 を 体感

React の useState 相当 を 純粋 JS で 再現。 状態 を 書き換える と、 UI が 自動で 追従。 NG パターン（直接ミューテーション）と OK パターン（イミュータブル更新）の 違い も 体感。

02.

Server vs Client コンポーネント 境界

ハンズオン

クリック で 境界 を 切り替える

05.

クイズ で ふり返ろう

3問チャレンジ

Q1. useState で 配列 を 更新 する とき **NG** な のは？
💡 push は 元配列 を ミューテート。 React は 参照 が 同じ と 判断 して 再レンダ しない。 必ず 新しい 配列 を 作って 渡す。
Q2. Next.js App Router で 「Client Component」 が 必要 な のは？
💡 イベント / フック が 必要 な 「葉」 だけ "use client"。 データ 取得 / レイアウト は Server。
Q3. Server State（API データ）の キャッシュ に 向く ライブラリ は？
💡 TanStack Query は 「再取得 / stale / 楽観的更新 / 無効化」 が 宣言的。 Zustand は Client State（UI 開閉 等）専用。
06.

きょうのまとめ

おぼえたこと

1

⚛️ UI ＝ f(state)

状態 を イミュータブル に 更新、 React が UI を 自動 同期。

2

▲ Server / Client の 境界 は 葉 に

データ取得 ／ レイアウト ＝ Server、 イベント が 必要 な 葉 だけ Client。

3

💎 状態 を 2つ に 分ける

Server State ＝ TanStack Query、 Client State ＝ Zustand / useState。
