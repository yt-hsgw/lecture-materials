# 高校生プログラミング塾 ／ 中級コース

## このコースのゴール

高校生・初級 までで「実務に近い 開発スキル」を 身につけた 受講者が、**チームで 本格的な Web サービス を 作って 運用する** レベルへ。 イメージは **「スタートアップ初日 から 戦力」**。

- **モダンFE フレームワーク**（React / Next.js）の 設計 思想を 理解する
- **状態管理**（Server State / Client State の 分離）を 自然に 行う
- **DB 設計再訪**（マイグレーション・インデックス・トランザクション）
- **キャッシュ層**（Redis）と **キューイング** の 基本を 体験
- **DevOps**（Docker / CI/CD / 監視）を 一人称で 設計できる

> 高校生・初級 が「自分の 環境と コードを プロ仕様 にする」 だったのに対し、高校生・中級 は **「チームで チームの コードを 動かし続ける」** が 主役です。 大学生インターン や 新人エンジニア の 入り口 と 同じ 解像度を 目指します。

## 各回の狙い

### 第1回｜チーム開発の現実
GitHub Flow / Git Flow の 違い、 **コードレビュー** が なぜ ボトルネックに なるのか、 **ペアプロ・モブプロ** の 使い所。 教室内で 「悪い PR」 と 「良い PR」 を 並べて 比較する。 設計 → 実装 → レビュー → マージ → リリース の 流れを 体感。

### 第2回｜フロントエンドフレームワーク
中学生・中級 で 触れた 素のHTML/JS から、 **React（コンポーネント思考） → Next.js（ルーティング・サーバーコンポーネント・APIルート）** への ステップアップ。 **Server State（API データ） と Client State（UI状態）** を 分けて 扱う。 状態管理ライブラリは **TanStack Query + Zustand** の 組み合わせを 推奨。

### 第3回｜バックエンドのスケール
中学生・中級 で 触れた SQL を **本気** で 設計し直す。 **正規化・インデックス・N+1問題・トランザクション**。 マイグレーション ツール（**Drizzle / Prisma**） で スキーマ変更を 安全に。 リード重い API に **Redis キャッシュ** を 追加して 体感する。 **DB は Turso** を 第1選択肢として 紹介。

### 第4回｜DevOps と監視
**Docker Compose** で 本番に 近い 環境を ローカルで 再現。 **GitHub Actions** で test → build → deploy を パイプライン化。 **Sentry / Datadog / OpenTelemetry** で エラーと パフォーマンスを 可視化。 **アラート設計** （何を どこに 通知するか）を 体験。

## 設計方針

- **チーム = レビュー + マージ**：1人で 完結 する PR を 作らない
- **本物の 規模を 体験**：データ 100万件、 同時アクセス 100 を 想定
- **Server / Client State 分離**：「画面の状態」と「サーバーの状態」を 混ぜない
- **観測可能性 ファースト**：ログ・メトリクス・トレース を 設計時から
- **Turso 第一**：軽量 SQLite × エッジ × レプリケーション の DX を 体験

---

## 危険ケース・注意

- **Next.js の Server / Client Component 混乱**：境界を 言語化して 統一する
- **N+1 クエリ**：ORM が 隠す 怖さを 体感（実行計画を 読む）
- **キャッシュ 無効化**：「キャッシュは 2つの 難問の うちの 1つ」 を 体験
- **個人情報 ログ流出**：Sentry に PII を 送らない 設定
- **依存関係の 脆弱性**：dependabot / Renovate を 使う

## 高校生・初級との 差分メモ

- 初級：「環境を 自分の ために コード化」 ／ 中級：**「チーム全員 同じ環境」**

- 初級：「TDD で 1機能」 ／ 中級：**「CI で test → build → deploy」**
- 初級：「Issue で タスク管理」 ／ 中級：**「スプリント で プロダクト 開発」**
