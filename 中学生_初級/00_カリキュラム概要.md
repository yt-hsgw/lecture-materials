# 中学生向けプログラミング塾 ／ 初級コース

## このコースのゴール

「コンピューターってなんだろう？」から始めて、**簡単なプログラムを自分で書いて動かし、開発の流れを言葉で説明できる**ところまで持っていく。

- パソコン、Web、インターネットのしくみを **中学生の粒度**（用語を正確に、概念は具体例つき）で理解する
- **Python**（または HTML/CSS/JavaScript）で、変数・条件分岐・繰り返し・関数を使った小さな構文を **自分で書いて動かせる**
- 「設計 → 実装 → テスト → 改善」という **開発の流れ** を、自分の小さな作品で体験する
- AIに頼んでみる・答えを確認する・**入れていい情報／だめな情報** を判断できる

> 小学生コースが「コンピューターってなに？」を体験で広げるのに対し、中学生コースは **「自分で書いて動く」** をゴールに据えています。専門用語は減らさず、具体例とともに正確に教えます。

## 各回の狙い

### 第1回｜コンピューターと開発環境
「コンピューターは命令を順番に実行する機械」を、**OS / ファイルシステム / エディタ / 実行環境** という4つの登場人物で説明する。VS Code と Python をセットアップし、`print("Hello")` を**自分の手で実行**する成功体験で締めくくる。**小学生コースの第1回より一段深く**、ターミナル／コマンドラインの最初の一歩まで踏み込む。

### 第2回｜Webとインターネットのしくみ
ブラウザに URL を入れた瞬間に何が起きているかを、**TCP/IP・DNS・HTTP** の役者で語る。HTML・CSS・JavaScript がそれぞれ「構造・装飾・動き」を担当することを、**DevTools の Elements / Network パネルで実物を見せながら**理解する。最後にローカルファイルで簡単な HTML を書いて、ブラウザで表示する。

### 第3回｜プログラミング基本構文
**変数・条件分岐・繰り返し・関数・リスト** の5つを、Python で順に体験する。最後に FizzBuzz をベースにした課題を解き、解けたら関数化してリファクタする。**「動いた」だけでなく、「同じ動きをよりキレイに書く」** という設計の入口を見せる。

### 第4回｜AI活用と開発の流れ
LLMが「次の単語を予測する確率モデル」であることを、**例えのレベルできちんと説明**する。プロンプトの作り方（だれに・なに・どう）を学び、AIに第3回のコードをレビューしてもらう。「AIは便利な道具だが、人間が確認する」を、**設計 → 実装 → テスト → 改善** の文脈で体験する。

## 設計方針

- **「動かす → 仕組みを知る → 設計する」の順**：先に動かして達成感、それから理屈、最後に「もっと良くするには」
- **専門用語は逃げずに使う**：かわりに必ず1度は具体例とセットで導入する
- **失敗例を見せる**：構文エラー、`NameError`、無限ループを意図的に出して、エラーメッセージを読む練習をする
- **AIに頼ることを否定しない**：ただし「自分で読めて、自分で直せる」状態を目指す
- **コードレビュー文化を体感させる**：他人のコードを読み、よい点を1つ言う／改善案を1つ出す練習を毎回入れる

---

## 危険ケース・注意

- **個人情報の取扱い**：AIサービスや公開リポジトリに、本名・住所・学校名・連絡先を入れない
- **APIキー・パスワード**：教材コード上にハードコードしない（`.env` 等の概念を第3〜4回で軽く触れる）
- **教室ネットワーク**：コマンドラインで外部にアクセスする場合、教室のネットワークポリシー・プロキシ設定を事前確認
- **実AIサービスの利用**：年齢制限（多くは13歳以上、規約で18歳未満は保護者同意が必要）、ログ保存の有無、生徒の同意を講師判断で確認
- **コピペ依存**：AIや既存コードからのコピペで完了させず、最低1行は自分で書く・説明できるルールを毎回置く

## 小学生・高齢者コースとの差分メモ

- 小学生：体験重視・専門用語控えめ・カードでの疑似プログラミング → 中学生：実コードで構文実行
- 高齢者：日常活用＋安全重視・GUI操作中心 → 中学生：ターミナル・エディタを使って能動的に作る
- AI回：小学生は「すごい・まちがえる」体験、中学生は「ペアプロ相手として使い、結果をレビューする」体験
